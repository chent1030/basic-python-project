# AI Agent 框架集成方案（最终版）

## 设计目标
在现有 FastAPI 模板中集成 `deepagents`（0.6.12）和 `agentscope`（2.0.5），建成一个支持**6 种拓扑、4 类记忆、可插拔中间件、可观测性、去中心化配置**的完整 agent 框架。

## 核心抽象：topology + runner
- 每个 agent 的 config.yml 声明 `topology` 字段。
- gateway 按 topology 路由到对应 **Runner**（运行器）；每个 Runner 封装一个库的编排能力。
- 成员 agent 引用其他 agent 目录（按 name），支持组合。

### 6 种拓扑与实现归属
| topology | 含义 | 实现库 / API | config 字段 |
|---|---|---|---|
| `single` | 单 agent + 工具循环 | deepagents 或 agentscope | `backend` |
| `subagent` | 主 agent 委派子任务（隔离上下文）| deepagents `subagents` + `task` 工具 | `subagents: [name...]` |
| `parallel` | 多 agent 并行跑同输入，汇总 | agentscope `FanoutPipeline` | `members: [name...]` + `aggregator` |
| `sequential` | 流水线，前者输出喂后者 | agentscope `SequentialPipeline` | `members: [name...]` |
| `conversational` | 多 agent 群聊讨论 | agentscope `MsgHub` | `members: [name...]` + `rounds` |
| `router` | supervisor 按意图分发 | 自建（LLM 分类 → 选 agent）| `routes: {intent: agent_name}` |

## 二、四类记忆体系
| 类型 | 实现 | 中间件 | 接入 |
|---|---|---|---|
| ① 上下文记忆 | **依赖后端原生**（deepagents checkpointer thread / agentscope 内置 memory）| `context_memory`（透传） | gateway 把拼好的 messages 喂进后端，context 交其自管 |
| ② 会话记忆 | `agent_sessions` 表（业务库）| `session_memory` | before 读历史、after 存本轮 |
| ③ 持久记忆 | **独立向量库** pgvector（与业务库隔离）| `persistent_memory` | before 向量召回、after 提取新事实写入 |
| ④ 外部记忆 | 第一期**外部 API**（http_client 召回）；pgvector 知识库/业务 DB 留接口 | `external_memory` | before 调外部 API 注入知识 |

四类各自成独立中间件，config.yml 独立挂载、独立排序（洋葱模型）。

```yaml
  - writer
```
**顺序流水线**（`content_pipeline/config.yml`）：
```yaml

  - summarizer
  - translator
  - proofreader
```
**并行**（`review_squad/config.yml`）：
```yaml

```
**协作对话**（`debate_room/config.yml`）：
```yaml

```
**路由**（`dispatcher/config.yml`）：
```yaml

```

## 五、统一 gateway（`gateway.py`）
**复用 `app.services.llm` 的 provider ChatOpenAI**，不重建 provider 管理。
```python
class AgentGateway:
    async def startup(self): ...           # registry 扫描 → 选 runner → 缓存
    async def shutdown(self): ...
    async def trigger(self, name, message, *, source="api", **vars) -> AgentResult
    async def trigger_stream(self, ...) -> AsyncIterator[str]
    async def chat(self, name, session_id, message, *, source="api") -> AgentResult
    async def chat_stream(self, ...) -> AsyncIterator[str]
    def list_agents(self) -> list[dict]
```
单例 `agent_gateway`，挂进 `main.py` lifespan（在 `llm.startup()` 之后）。

### run 流程（拓扑分发 + 中间件洋葱 + 树状记录 + 日志）
```
run(name, message, source, session_id?, parent_run_id=None, depth=0):
  1. AgentRunContext(name, source, session_id, message, logger, parent_run_id, depth)
  2. logger.info("agent start", agent=name, source=source, depth=depth)
  3. run_id = RunStore.create(parent_run_id=parent_run_id, depth=depth, status=running)
  4. middleware.before_invoke(ctx): session/persistent/external 读、filter 输入、context 透传
  5. runner = pick_runner(cfg.topology)
     runner.run(ctx):  # 成员 agent 调用各自走 run(..., parent_run_id=run_id, depth+1) → 形成调用树
  6. middleware.after_invoke(ctx, result)  # 逆序: filter/persistent/session/tracing
  7. RunStore.update(run_id, status=succeeded, output, duration_ms)
  8. logger.info("agent done", agent=name, run_id=run_id)
  except: RunStore.update(run_id, status=failed, error); logger.exception(...)
```
**树状记录**：每个成员/子 agent 调用都写一条 `agent_runs`，带 `parent_run_id` + `depth`，可还原整棵调用树。

### runner 分发
```python
RUNNERS = {
  "single": SingleRunner, "subagent": SubagentRunner,
  "parallel": ParallelRunner, "sequential": SequentialRunner,
  "conversational": ConversationalRunner, "router": RouterRunner,
}
def pick_runner(topology) -> BaseRunner: return RUNNERS[topology]
```

## 六、数据表（3 张）+ 迁移
遵循 `item.py` typed `Mapped`/`mapped_column`，注册到 `app/models/__init__.py`。
- **agent_sessions**：`id, session_id(idx), agent_name(idx), role, content(Text), created_at`
- **agent_runs**（树状）：`id, run_id(uuid,idx), parent_run_id(null,idx), depth(default 0), agent_name(idx), trigger_source, session_id(idx,null), input(Text), output(Text,null), status(running/succeeded/failed), started_at, finished_at, duration_ms, error(null), tokens(null)`
- **agent_memories**（持久记忆，独立向量库）：`id, agent_name(idx), user_id(idx,null), content(Text), embedding(Vector pgvector), metadata(jsonb), created_at`
- 迁移：`alembic revision --autogenerate -m "add agent_sessions/runs/memories"`

## 八、中间件系统（洋葱模型，6 个）
```python
class MiddlewareBase:
    name: str
    async def before_invoke(self, ctx) -> ctx: ...    # 可改 messages
    async def after_invoke(self, ctx, result) -> result: ...  # 可改 result
```
| 中间件 | before | after | 第一期 |
|---|---|---|---|
| tracing | 记录开始 | 步数/耗时 + 结构化日志 | 完整 |
| context_memory | 透传(交后端原生) | 标注来源 | 完整(薄) |
| session_memory | 读历史拼 messages | 存本轮消息 | 完整 |
| persistent_memory | 向量召回注入 | 提取新事实写入 | 完整(pgvector);未配 stub |
| external_memory | 调 API 取知识注入 | — | 完整;未配 stub |
| filter | 输入过滤/PII 脱敏 | 输出审核 | 完整,规则可配 |

## 设计取舍说明
- **6 拓扑全覆盖，按库强项分工**：子 agent/单深度走 deepagents，并行/顺序/协作走 agentscope，路由自建。拓扑由 config.yml 声明，gateway 按 topology 选 runner。
- **树状运行记录**：parent_run_id + depth 还原整棵调用树，多拓扑下每个成员/子任务可监控。
- **四类记忆职责分明**：context 交后端原生（不重复造）；session 走业务库；persistent 走独立向量库；external 第一期走外部 API。
- **每类记忆独立中间件**：洋葱模型独立挂载/排序。
- **去中心化**：agent 列表在 `app/ai/agents/<name>/config.yml`，成员可复用。
- **可观测性双重**：结构化日志（实时，复用 get_logger+request_id）+ agent_runs 树（持久可查询）。
- **gateway 复用 `app.services.llm`**：单一 provider 真相源。
- **两 backend 隔离**：库特有能力在各自适配器/runner 内。
