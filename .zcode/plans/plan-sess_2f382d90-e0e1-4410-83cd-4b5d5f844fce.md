# Harness 框架设计方案

## 设计目标
通用 harness 框架:预处理层 → agent 处理层,检查项一文件一个+自动发现。
Stage 间用统一 Context 对象传递(文本/图片/结构化数据)。
复用 app/ai 的 llm/工具/http_client/config/logging,重写编排层。

## 核心抽象:Pipeline → Stage → Check

```
Pipeline(一次业务流程,如文档审核)
  ├── Stage: preprocess   预处理(下载/文件类型判断/图片分割放大)
  ├── Stage: ocr          OCR(MinerU,返回文本+处理后的图片)
  ├── Stage: extract      章节提取
  ├── Stage: checks       并行检查(每个 Check 一个文件,自动发现)
  └── Stage: report       汇总报告
```

### 统一 Context 对象(Stage 间数据载体)
```python
@dataclass
class HarnessContext:
    """贯穿整个 Pipeline 的上下文,每个 Stage 读/写它。"""
    # 输入
    entity: dict              # 业务数据(EhsConstruct 等,比对基准)
    file_url: str             # 原始文件 URL
    # Stage 产出(逐步填充)
    file_type: str = ""       # image/docx/pdf(预处理判断)
    raw_file: bytes = b""     # 下载的原始文件
    processed_images: list[str] = []  # 预处理后的图片 URL/base64(分割+放大后)
    ocr_text: str = ""        # OCR 结果文本(markdown)
    ocr_images: list[str] = [] # OCR 返回的图片
    sections: dict[str, str] = {}  # 提取的章节
    check_results: dict = {}  # 各检查项结果 {name: CheckResult}
    report: dict = {}         # 最终报告
    # 元信息
    pipeline_id: str = ""
    metadata: dict = field(default_factory=dict)  # 自由扩展
```

### Check 基类(一文件一个检查项)
```python
class BaseCheck:
    """所有检查项的基类。一个文件定义一个检查项,自动发现。"""
    name: str                    # 检查项名
    description: str             # 描述
    sections: list[str]          # 需要哪些章节("full"/"cover"/"tail"/标题关键词)
    check_type: str = "ai"       # "ai"(调LLM) | "rule"(纯代码) | "hybrid"

    async def run(self, ctx: HarnessContext) -> CheckResult:
        """执行检查,返回统一格式的结果。子类实现。"""
        raise NotImplementedError

    def get_input(self, ctx) -> str:
        """从 ctx 取本检查需要的章节内容(根据 self.sections)。"""
        ...
```

```python
@dataclass
class CheckResult:
    """检查结果的统一契约。所有检查项都返回这个。"""
    name: str
    passed: bool
    severity: str = "info"        # high/medium/low/info
    issues: list[str] = field(default_factory=list)
    suggestion: str = ""
    detail: str = ""
    raw: dict = field(default_factory=dict)  # 原始数据
```

## 各部分详细设计

### 一、context.py — Context + CheckResult
(如上所示的 HarnessContext + CheckResult dataclass)

### 二、base.py — BaseCheck + BaseStage
- BaseCheck:name/description/sections/check_type + run(ctx) + get_input(ctx)
- BaseStage:name + async run(ctx) → 修改 ctx

### 三、pipeline.py — 编排器
```python
class Pipeline:
    def __init__(self, stages: list[BaseStage]):
        self.stages = stages

    async def run(self, entity: dict, file_url: str) -> HarnessContext:
        ctx = HarnessContext(entity=entity, file_url=file_url, pipeline_id=uuid4())
        for stage in self.stages:
            ctx = await stage.run(ctx)  # 每个 stage 读/写 ctx
        return ctx
```

### 四、checks 自动发现(关键:可扩展性)
仿 scheduler._scan_tasks_package:
- 扫描 app/harness/checks/*.py
- 每个文件定义一个 BaseCheck 子类(模块级变量 `CHECK = XxxCheck()`)
- registry 收集所有 CHECK,自动注册
- **加检查项 = 加一个 .py 文件,零配置、零改代码**

### 五、preprocess.py — 文件预处理(独立层)
```python
async def preprocess_file(ctx: HarnessContext) -> HarnessContext:
    """预处理:下载文件 → 判断类型 → 图片分割放大。"""
    # 1. 下载文件(http_client)
    ctx.raw_file = await download(ctx.file_url)
    # 2. 判断类型(扩展名/magic bytes)
    ctx.file_type = detect_type(ctx.raw_file)
    # 3. 如果是图片:长图分割成4份 + 放大8倍;小图也放大
    if ctx.file_type == "image":
        ctx.processed_images = await split_and_enlarge(ctx.raw_file)
    return ctx
```
用 Pillow 做图片处理(分割 Image.split + 放大 Image.resize)。

### 六、Check 的两种实现风格(都可自动发现)

**AI 类检查项**(app/harness/checks/typo_check.py):
```python
class TypoCheck(BaseCheck):
    name = "typo"
    sections = ["full"]
    check_type = "ai"
    async def run(self, ctx):
        doc = self.get_input(ctx)
        prompt = f"检查错别字:{doc}"
        result = await llm.invoke([{"role":"user","content":prompt}])
        return CheckResult(name="typo", passed=..., issues=[...])
CHECK = TypoCheck()
```

**规则类检查项**(app/harness/checks/signer_check.py):
```python
class SignerCheck(BaseCheck):
    name = "signer"
    sections = ["tail", "cover"]
    check_type = "rule"
    async def run(self, ctx):
        # 纯代码判断,不调LLM
        reviewer = extract_name(ctx, "校对人")
        approver = extract_name(ctx, "批复人")
        passed = reviewer != approver
        return CheckResult(name="signer", passed=passed, ...)
CHECK = SignerCheck()
```

## 文档审核 Pipeline 组装
```python
# 在 service 或 endpoint 里组装
def build_doc_review_pipeline() -> Pipeline:
    return Pipeline(stages=[
        PreprocessStage(),     # 下载+类型判断+图片分割放大
        OcrStage(),             # MinerU OCR(发处理后的图片/文件,拿文本+图片)
        ExtractStage(),         # 章节提取
        CheckStage(),           # 并行跑所有自动发现的 checks
        ReportStage(),          # 汇总报告
    ])
```

CheckStage 内部:
```python
class CheckStage(BaseStage):
    async def run(self, ctx):
        checks = registry.all_checks()  # 自动发现的所有检查项
        results = await asyncio.gather(*[c.run(ctx) for c in checks])
        ctx.check_results = {r.name: r for r in results}
        return ctx
```

## 可扩展性(解决你的核心痛点)
- **加检查项**:在 app/harness/checks/ 加一个 .py 文件,定义 BaseCheck 子类 + `CHECK = XxxCheck()`。自动发现,无需改任何其它代码。
- **加预处理步骤**:BaseStage 子类,加到 Pipeline 的 stages 列表。
- **复用现有能力**:llm.invoke 调 LLM、@tool 工具系统、http_client、config、logging 全部复用。
- **统一契约**:所有检查项返回 CheckResult(统一格式),汇总不用猜格式。

## OCR 图片处理流程(解决你的具体需求)
```
文件进来 → preprocess 判断类型
  ├── image → 长图?切4份 : 整图 → 每份放大8倍 → processed_images
  ├── docx  → 转 PDF/图片(或直接给 MinerU)
  └── pdf   → 直接给 MinerU
→ OcrStage: 把 processed_images/文件发给 MinerU → 返回 ocr_text + ocr_images
```

## 与现有框架的关系
- **并存**:新框架 app/harness/ 和现有 app/ai/ 并存
- **复用**:llm / @tool / http_client / config / logging(底层能力)
- **重写**:编排层(pipeline/stage/check 替代 agent_gateway/CHECKS)
- **不动**:现有 app/ai/ 的 agent 框架保留(其它功能还在用)

## 落地顺序
1. context.py(HarnessContext + CheckResult)
2. base.py(BaseCheck + BaseStage)
3. registry.py(检查项自动发现)
4. preprocess.py(文件下载+类型判断+图片分割放大)
5. pipeline.py(Pipeline 编排器)
6. checks/(6 个示例检查项:typo/heading/table/cover/seal/signer)
7. stages.py(Preprocess/Ocr/Extract/Check/Report 5 个 Stage)
8. 端点改造(用新 Pipeline 替代旧 doc_review service)
9. 测试 + lint
