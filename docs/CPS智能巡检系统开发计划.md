**职责切分原则**（PRD 26.1）：

- **Java 库 = 业务事实唯一真相源**：问题单、整改提交版本、初审任务与意见（供审核台）、巡检计划与业务任务、辅房/点检/台账、事项权限与审核员配置。业务状态机、权限、审计流转归 Java。
- **Python 库 = AI 执行与运行时**：Agent 编排（PRD §11 七对象运行态）、初审执行记录（模型版本/耗时/错误）、周报运行记录与文件、长期记忆、语音转写。
- **跨库只通过 API 交换业务 ID 字符串**（如 `cps_issue.agent_inspection_id` 既有模式），禁止跨库外键、禁止 Java 直连 PG / Python 直连 MySQL。
- **AI 无决定权**：Agent 产出一律以"意见/建议"身份回写，不拥有关闭、退回、扣分的决定权（PRD §28.1、§24.2、§2.3）。
- **网络边界**：用户认证终止于 Java；Java→Python 沿用 `internal_trust + trusted_networks`，网段收敛为后端专用，终端禁止直连 Python。

### 2.2 Agent 架构分层

| 层 | 组成 | 职责与边界 |
|---|---|---|
| L0 Runtime（LangGraph） | InspectionState、Checkpoint、interrupt/resume、事件流 | 只做运行时基础设施，**不预定义业务节点顺序**（PRD §7.2）；图的边是"决策循环" |
| L1 主 Agent（决策层） | CPS 主 Agent | 读状态/记忆/规则/人工反馈 → 提议下一步 Agent（含理由、前置条件、预期输出）→ 调度确认卡 → interrupt 等人工 → 执行被选 Agent → 再决策；max_rounds 防链过长 |
| L2 专用 Agent（执行层） | 问题识别/整改判断/历史分析/覆盖分析/报告/计划 + AI 初审组件 + 辅房点检判定 | 无状态、可单测；结构化输出（结果/证据/置信度/异常）；不直写历史库与生产记忆；工具白名单（PRD §6.1） |
| L3 DeepAgents | 复杂分析内循环 | 历史趋势、报告汇总、未覆盖分析、复杂证据比对；**简单视觉判定与确定性检查不得包 DeepAgents**（延迟成本不可接受） |
| L4 旁路观察 Agent | 事件日志消费者 | 产出候选记忆/失败模式/优化建议；不控制流程、不改主 Agent 策略；审核后才生效（PRD §8） |

**确定性规则与模型判断严格分离**（ADR-004）：字数（L≥15）、标点比例（10×P≤L 整数精确比较）、库存阈值、评分排名、统计指标由代码计算并记录实际值；模型只负责视觉、语义与解释（PRD §29.2、§16）。

### 2.5 关键机制设计要点

**（a）AI 初审异步管线**（PRD §28.4、§29；AC-16/17/18/27）

- 选型：**任务表 + 内嵌异步，不引入独立 MQ**（日百级频率、分钟级容忍；接口抽象为 Transport 未来可换）。
- 时序：整改提交（Java 事务）→ 创建 submission v_n 锁定 → `PENDING_AI_REVIEW` → task(RUNNING, submitted_at=now, timeout_at=+600s) → 事务后投递 C-01 → Python 执行（确定性规则先行毫秒级 → 视觉/语义并行调模型）→ 回调 C-02。
- 三态：Java 30s 定时扫描，`RUNNING && now≥timeout_at` → `TIMEOUT_OPEN`（超时≠失败）；显式失败 → `FAILED` 立即可接管；界面必须区分运行中/执行失败/超时可接管。
- 技术重试 ≤2 次（30s/60s 退避），**重试不重置计时**（计时锚 submitted_at）；整任务 wall-clock 8 分钟强制中断留接管余量。
- 接管：reason 必填，接管后直接人工裁决；迟到 AI 结果 → `LATE_RESULT` 仅留痕，不覆盖裁决、不推进流程。
- 版本绑定：意见挂 submission_id，退回重提生成新版本必触发新初审，旧版本不覆盖新版本。

**（b）文本规则确定性计算**（PRD §29.2；AC-17/24）——必须代码实现，禁模型估算

- 换行（含 U+2028/2029）剔除后 `L = len(S)`，**空格计入 L**；中英文标点 + 空格均计入 `P`（出现次数非种类数）。
- `……`（连续两个 U+2026）状态机整体消耗：P+1、不计连续；在 L 中按实际字符数计量。
- 连续标点违规（`， 。` 中间空格属标点类，不能插空格绕过）；空文本无除法天然防除零。
- 判定：`L ≥ 15` 且 `10 × P ≤ L`（整数精确比较防浮点）；三字段（原因/短期/长期）分别独立计算，禁止合并凑字数。
- 边界单测固化：`L=15,P=1`✓ `L=15,P=2`✗ `L=20,P=2`✓（恰 10% 满足）`L=14,P=0`✗ 空文本✗ `……`✓；L/P 实际值随意见落库供审核专员核对。

**（c）幂等键规范**（PRD §5.5-6、§13、§22）

统一 `{domain}-{entity}-{natural-key}[-{version}]`，数据库唯一索引兜底：`cps-rectify-{issueId}-v{n}`（初审）、`initial-review-result-{taskId}`（回调）、`weekly-{type}-{period_start}`（周报）、`plan-task-{planId}-{itemId}`（建单，**补建仅扫 CREATE_FAILED，已成功项不重复创建**，AC-30）、`room-judge-{submissionId}-{itemId}-{attempt}`（重拍新 attempt）、`notify-{alertEventId}-{channel}-{date}`（预警合并期防重发）。跨系统写 = 本地事务 + outbox + 至少一次投递 + 消费端去重。

**（d）周报定时调度**（PRD §21；AC-28/29）

- APScheduler 显式 `timezone="Asia/Shanghai"`（容器 TZ 不可靠），cron 周一 08:00；窗口 `period_end=本周一00:00`、`period_start=−7d`，左闭右开。
- 分类各自生成、独立运行记录与文件；巡检分类清单配置驱动（先落 CPS 问题巡检、辅房点检两类）。
- 状态机：生成中/生成失败/上传中/上传失败/已归档 + **独立 push_status**；上传成功≠推送成功；未接渠道 = `UNCONFIGURED` 显示"推送未配置"。
- 免审全自动（21.1-7 例外条款，不外溢到计划审核）；漏跑启动补偿扫描；重跑生成新版本文件（object key 带 run_no）不覆盖历史。

**（e）辅房点检判定与计分**（PRD §23-24；AC-07~11/31/32）

- 三段门控：类型匹配（不符必须重拍，不进合格判断）→ 内容判断（PASS/FAIL+理由）→ 证据可用性（模糊/遮挡→UNJUDGEABLE 补拍，不默认通过）；类型与内容共同进入模型输入；同步调用控制现场延迟。
- 类型不符/无法判断不扣分、不得手工改合格绕过提交；提交前本人可改有效结果（留 AI 原始值/修改人/时间/原因）并重算分；提交后锁定，无管理员重开。
- 单次 `max(0, 100−Σ不合格适用项扣分)`；周期总分=自然周内已提交有效记录单次得分**之和**（不均分/不最新分，AC-31：A 两次 80+90=170 > B 一次 100）；得分与检查时间分字段关联同一记录；未完成/无效记录不计满分。

**（f）库存事务**（PRD §25；AC-13/33）

出入库单事务：`SELECT ... FOR UPDATE` 行锁 → 出库校验 `quantity ≤ stock_before`（禁负库存，DB CHECK 兜底）→ 更新 + movement 快照 → 预警评估：`stock_after ≤ alert_qty`（**等于也触发**）→ upsert ACTIVE 事件（同 item+room 合并）；`> 阈值` 且有 ACTIVE → RESOLVED；再次不足成新事件。通知端口抽象（渠道待确认，对齐周报"未配置不伪造成功"模式）。

**（g）长期记忆链路**（PRD §8-9）

事件日志 → 观察 Agent（批量低峰，频率待定）→ MemoryCandidate（场景/证据/来源/置信度/适用范围，§9.2 十项字段完整落库）→ 管理员审核 → LongTermMemory 版本化（启用/停用/回滚/追溯）→ 反哺主 Agent 推荐/相似案例/采集提示/完整性检查。硬约束：候选与生产隔离；低置信未验证不升强规则；记忆只作参考**不得绕过人工确认**。
